Phone onboarding

On first launch the phone has no machine, so it opens on an empty Machines page with Add machine and Settings. The desktop greets you with three steps over the sky: what zz is, import your configs, the agent hook. Neither of the last two means anything on a phone. What a phone needs first is a machine. Until it is connected to one it cannot list the tailnet either, so the first machine is always typed. Same sky, same text at the bottom; the phone versions put the action in a full-width 56 button. Copy is a draft except the welcome, which is the desktop's.

A. Three steps, like the desktop

Welcome, connect a machine, notifications. The connect step is the form: field, Connect. Skip in the corner lands on Machines. The third step stands in for the desktop's hook: one switch, and Start asks iOS for permission.

B. Two steps

Welcome, then connect. No notification step: iOS already asks the first time an agent waits on you, which is the moment the question makes sense.

C. One screen

The welcome and the field together. Nothing to page through: read one line, type the machine, go.

D. Welcome, then the Add machine sheet

One new screen. Its button opens the Add machine sheet the Machines page already has, over the sky. Least new UI; the sheet carries Copy SSH key and, once a machine is connected, the tailnet list.

E. Connect one, then your tailnet (picked)

Auto-detect needs one machine first: the phone cannot read the tailnet itself, it asks the first machine it reaches (tailnet hosts) and probes each answer. So the second step is the first machine, typed or scanned from the code desktop Settings › Hosts shows, and the third lists what that machine found, the way the desktop's import step lists found configs: a switch each, on for every one that answers. No tailnet, or nothing found, skips it.
