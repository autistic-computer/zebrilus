# What goes sideways now

## 1. The follow-up line starts a thank-you loop (2 of 3 Codex-host m4c runs)

Every finished report now ends with `Follow up with: zz agent-send -t %2 'TEXT'`. After the
child's static answer, a Codex host acknowledged it with `agent-send`. The child replied to the
acknowledgement, that reply came back with the same line, and the host acknowledged again.
`88Nd2E` sent 24 messages over 139 s before it stopped by itself ("I'm stopping the repeated
check-ins"); `m9tQ0T` sent 3 after its real follow-up:

```
> [zz] %2 (claude) finished:
  Running `./stamp.sh` would print one line of the form `stamp: ` followed by 8 random lowercase hex digits ...
  Follow up with: zz agent-send -t %2 'TEXT'
$ zz agent-send -t %2 'Thanks. That answers the question; keep stamp.sh unexecuted and make no workspace changes.'
> [zz] %2 (claude) finished:
  Understood. I won't run `stamp.sh` and I won't change anything in the workspace. ...
  Follow up with: zz agent-send -t %2 'TEXT'
$ zz agent-send -t %2 'Confirmed. No more follow-up is needed; leave the script and workspace untouched.'
...
```

Smallest change: make the line conditional: `If the reply answers the user, answer the user now.
Only if something is missing: zz agent-send -t %2 'TEXT'`.

## 2. A Codex child does not escalate when the script's own output carries the error (3 of 3 Claude-host m4)

The note with "even if your brief says to stop on failure" reached the child in all three runs.
The blocked write shows up as a line the script printed (`./stamp.sh: line 4: ./stamped.txt:
Operation not permitted`, exit 1), and the task is to report what the script printed, so the
child reports it. The rig's m4c brief has no permission wording, and there the children
escalated every time. More note text is unlikely to fix this for a weak model. Smallest
behavior change: when Codex reports that a child's command was denied by its sandbox, the
driver raises the ask to the host itself ("%2's command was blocked by its sandbox: rerun it
outside? allow/deny").

## 3. m4c Claude host: the script still runs once, read-only, before the ask (3 of 3)

Same as the second batch: `./stamp.sh` runs read-only, fails, is rerun with escalated
permissions, and only that rerun asks; each host answered `--deny`. Not a text problem.
