# Concepts

* [Accelerated OSR compositing & external begin frames](accelerated-osr-compositing.md) - The plan that replaced the CPU BGRA readback pipeline with CEF shared GPU textures and phase-locked Chromium to zz's frame clock via external BeginFrames; shipped on Linux, macOS, and Windows, with external BeginFrames still unsupported on Windows.
* [Agent backbone v3 - browser over CDP, typed agent state, headless completeness](agent-backbone-v3.md) - Handoff plan from the 2026-09-09 headless audit of what an AI agent can drive through the zz CLI - the verified working set, the verified gaps, the locked decisions (zz is the browser process and the agent brings its own CLI, no MCP server, no native snapshot verbs before measurement), and three lanes of work with file pointers, acceptance checks, and traps.
* [Daemon-owned agent runtime](agent-daemon-runtime.md) - The agent pane's ACP adapter runtime moved from the GUI into the daemon: daemon-spawned adapter children, a daemon-side journal with replay-then-tail attach, a dedicated coalescing outbound lane, and clients reduced to viewports, so agent runs survive client detach and every client kind can render them. Since 2026-10-23 the Agent pane is gone and the runner on this host and fanout is the agent lens over terminal panes.
* [Agent lens . the agent view of a terminal pane](agent-lens.md) - zz stops drawing its own agent pane. Claude Code and Codex run as their real TUIs in ordinary terminal panes, and a terminal running one of them gets a lens button in its header that swaps the cell grid for the agent timeline of that same pane. The daemon tails the transcript the CLI already writes (Claude's session jsonl, the rollout Codex holds open) through the existing translators, the lens composer pastes into the TUI, and a Claude permission prompt is answered with the keys the TUI takes. The Agent pane kind, its pickers and every place that treats it as a pane type are deleted; the native drivers stay for the lead chat.
* [Agent pane text projection](agent-pane-projection.md) - Removed 2026-10-23 with the Agent pane. Every Agent pane owned a PTY-free shadow TerminalSession fed with a text projection of its transcript (prompt between OSC 133 A/B and C, reply as output, D plus BEL at turn end), so capture-pane, show-last-output, pipe-pane, and activity/bell alerts worked on agent panes with no new verbs. Agents now run in real terminal panes, which the tmux read verbs already cover.
* [Agent turn machine . one owner for "a turn is running"](agent-turn-machine.md) - One pure state machine in the daemon decides whether a native driver's turn is running, waiting, cancelling or done, from a small set of facts the Claude and Codex drivers report. It replaces the six turn flags spread over the drivers, the host, the fanout lane and the desktop client. zz-machine holds the shape (transition, decision, wake time from the state). The Claude and Codex drivers run it and replay their recordings through it in tests; the host, fanout lane and clients mirror the turn events instead of deriving their own.
* [Client core & contract - one brain, every face](client-core-and-contract.md) - Decision record for the shared client contract - protocol-owned commands and keys, sans-IO reduction, typed Agent attention, and a native-shell C ABI.
* [Command stream channel](command-stream-channel.md) - One bounded channel for the caller's standard input and output on a command client: a capped whole read for the sinks that hold their payload, a chunked stream with backpressure for pane input, one byte-preserving carrier on the invocation, and three named sinks, so `source-file -`, `display-message -I`, `split-window -I`, `load-buffer -` and `save-buffer -` share a transport instead of owning five.
* [Daemon performance rebuild](daemon-perf-rebuild.md) - The campaign to bring the zz daemon to tmux cost per command, per pane and per attach while keeping the 5x output throughput lead - a permanent zz-vs-tmux gate first, then waves that remove unrequested work (one-frame Exec commands, change-driven publication, lazy formats, frames only for watchers, a compact wire under one unreleased protocol version), then one mux loop and PTY shards; the lane brief source with targets, merge order, write zones, gates and rollback switches.
* [Design system: tone, emphasis and ground](design-system.md) - How zz chrome picks colors and shapes: every filled, tinted or outlined widget names a tone (what it means) and an emphasis (how loud it is), the theme turns the pair into one Paint on the ground it sits on, planes name an elevation, every surface takes its fill, edge, corners and shadow from its surface role, and clippy rejects hand-mixed washes, opacities, borders and shadows outside the kit.
* [Durable lead chat . one lead, any machine](durable-lead-chat.md) - How the lead agent survives restarts and moves between machines without replaying its history: zz keeps a small chat log, the lead keeps a ledger it rewrites every turn, and a restarted lead is a fresh Claude Code or Codex session started from a 2-4 KB packet built from the two, while the vendor transcript stays where it was written. One host owns the lead under an epoch and mirrors the small files over zz's own ssh link. Measured against full transcript resume with mid-task kills on the fleet; prototypes in scripts/lead-checkpoint.py and scripts/lead-sync.sh.
* [Flat sidebar data: pane summaries, attention and time](flat-sidebar-data.md) - The data layer for a flat, two-line-per-window sidebar on every client: one PaneSummary per pane in the tree (last change time, unseen finish latch, last shell command, @name, display cwd and git branch, and the program running in a terminal), one status record for every agent kind, the daemon clock on the handshake, and a renderer-free view model in zz-client. Both data slices are built, and the desktop, web and iPad sidebars draw it when the footer's eye switch is on.
* [Fleet attach . one GUI, every daemon](fleet-attach.md) - Design and v1 record of one GPUI client aggregating sessions from every machine running a zz daemon - host-keyed connections, a merged multi-host sidebar tree, ssh-forwarded sockets behind a transport-agnostic endpoint seam; daemons never talk to each other.
* [Fleet pairing and discovery - automatic sidebar pairing](fleet-pairing.md) - Retired design record (2026-08-01) for app-lifetime discovery, contextual sidebar pairing, target-side one-time-code dialogs with a native daemon-only fallback, automatic two-way QUIC trust, and the mDNS-signaled firewall knock.
* [Floating panes . the popup becomes window-owned](floating-panes.md) - Floating panes as flagged leaves of the window's layout tree, exactly where tmux 3.8 keeps them, with display-popup rebuilt as a modal floating pane the way tmux master 34cd5da4 does it; covers the 3.8 command surface including windows with no tiled pane, the appended v108 wire, sizing, zoom, hit-testing, mouse drags, what each client draws, and the float.core, float.clients and float.keys lanes with their acceptance clauses.
* [Input-reliability audit and hardening plan](input-reliability-audit.md) - The 2026-08-03 four-sweep audit of the bug classes behind the dead-chord field reports . stale-context panics, silent command failures, focus-path listener gaps, strandable pairing state, and stale memo digests . with every confirmed site and the agreed fix order.
* [Interface themes: materials, roles and colors in one file](interface-themes.md) - A theme is one JSON file holding its materials, how each piece of UI uses them (its roles), and the colors it is drawn in for light and for dark, so it can imitate a whole app; the mode only picks the color set. Default, macOS and Yaru ship built in. Settings draws the theme with an accent and a background tint over it, and saves the result as a theme; the 34 old palette presets, the color and material presets, Flat/Modern/Full, the chrome color overrides, the nine-key look and the per-material keys are gone.
* [Layered configuration & native settings view](layered-config-and-settings-view.md) - The decision record behind zz/config, daemon-owned keys crossing the wire, and native settings with split shortcut controls and a mux.conf editor.
* [Multi-device attach . every machine, same session](multi-device-attach.md) - Agreed plan to lift the one-interactive-client-per-session rule so all of the user's devices can attach to one session at once - per-client viewports and window focus, latest-active-wins PTY sizing, presence decorations, and steal-attach falling out for free.
* [Native agent drivers](native-agent-drivers.md) - The daemon's native drivers speak each vendor's own protocol (they drove the Agent pane until it was removed on 2026-10-23). Claude Code runs over stream-json and its control protocol, Codex over a private `codex app-server` per pane, and ACP stays for the agents that speak it natively, all emitting the stream the shared reducer already renders.
* [Native status bar for GUI clients](native-status-bar.md) - The desktop status bar combines the sidebar toggle, left-aligned window pills, and agent activity from structured state while tmux status rows remain a TUI compatibility surface.
* [Shell path picker and which-key](path-picker-and-which-key.md) - Shipped plan for two desktop overlays over protocol v107 - a path picker anchored at the terminal cursor whose listing, git marks, and insert style come from the daemon that owns the pane while the client ranks and pastes, and a which-key sheet that follows the prefix and custom key tables through a new KeyTableActive event, with the stock notes brought to tmux parity.
* [PiP panes . every float, thrown to one of nine places](pip-panes.md) - In the GUI clients every floating pane that is not modal draws as a PiP: the pane in a card that casts the float shadow, with the same header as a tiled pane, tile back and zoom in place of the splits. Drag the title to throw it, iOS style, onto one of the nine places move-pane -P names. PiPs on one place fan out so each header shows, and they slide off the side edge, 60 px left showing, while a tiled pane has focus. Underneath it stays a tmux 3.8 float with no new flag, state or wire.
* [Remote browser egress . ssh -D with zero setup](remote-browser-egress.md) - Routing a remote session's browser pane traffic through the attached ssh host - the composite CEF profile points its proxy preference straight at `ssh -D` (socks5-direct), sshd resolves and dials remotely, client-local cookie jars stay keyed (profile, egress-host), and there is zero zz proxy code on either end. Shipped on QUIC (v41), deleted with that transport, reintroduced on ssh and simplified to socks5-direct 2026-08-07.
* [Adaptive in-flight window for remote attach](remote-flow-window.md) - Keystroke echo no longer waits behind seconds of screen data over ssh - the daemon pings inside its own output stream, the client answers, and the daemon keeps unanswered bytes under measured rate times RTT, so frames coalesce in the mailbox instead of queueing in sshd and TCP; local unix clients keep the old path. Built on protocol v110 with two-machine measurements; in review as a PR.
* [Scene-streaming remote attach ("mosh for GUIs")](scene-streaming-remote.md) - Partially retired 2026-08-01. QUIC/zstd/predictor deleted; surviving pieces (history ring, RequestFull, local-scroll, reconnect) plus zz attach are current. Historical record of the scene-streaming campaign.
* [Surface roles: shared materials composed per piece of UI](surface-roles.md) - A theme defines its materials once (radius, corner smoothing, outline width, contact and float shadows, glass, primary, row inset) and every distinct piece of UI is a role that picks from them with seven props (fill, outline, shadow, shape, smoothing, hover, selected), resolved from its kind's built-in style and each group's built-in patch, then the theme's patches from the kind inward, so a theme's patch for a kind beats every built-in in it. Built 2026-10-13; regrouped 2026-10-14 into 10 broad kinds (bars, panels, panes, cards, floating, buttons, items, fields, labels, dividers) with groups under them, 60 zz roles in zz_ui::roles, every call site painting through Theme::layer, plus the inventory of about 450 painted pieces it was drawn from.
* [Terminal bell . Ghostty-parity notifications](terminal-bell.md) - Shipped plan to stop swallowing BEL - register libghostty's on_bell in the daemon, carry a per-pane bell flag in mux state and the snapshot plus an appended EventPayload edge event, badge the pane's sidebar icon, render a `!` window flag, request window attention and play the macOS system beep on the ring edge, clear on pane input, selection, or window activation; no OS notification popup, no config in v1.
* [tmux drop-in plan](tmux-drop-in.md) - The original alias-tmux=zz campaign and its shipped phases, followed by the live compatibility ledger: tmux names retain tmux meaning, zz power uses superset verbs, and linked windows plus real-tmux socket interop stay excluded.
* [tmux-compatible CLI and native superset roadmap](tmux-superset-roadmap.md) - The dependency plan and delivery history for making alias tmux=zz practical while keeping picker, browser, agent, editor, and fleet behavior on explicit zz-only commands.
* [TUI client - zz in a terminal, browsers included](tui-client.md) - A second presentation backend that renders zz sessions in a raw TTY - cell blit for terminals, text views for agents, kitty-graphics CEF frames for browsers - turning the GUI into one of three faces of the daemon.
* [Per-pane TUI customize mode](tui-customize-mode.md) - Port mode-tree.c and window-customize.c onto the server pane mode stack, and share one prompt editor between customize-mode and switch-mode.
* [TUI parity campaign](tui-parity.md) - The terminal-client parity contract: tmux observable behavior by default, zz additions through superset commands, and proof tied to the tested revision.
* [Artifacts . agent-written HTML in browser panes and inline](userpanes.md) - Proposed plan for showing HTML an agent writes. zz html <path> registers the page with the daemon that ran the caller, browser panes load it from a zz://<token>/ scheme whose bytes the daemon sends over the client's existing connection (so it works on ssh hosts), the daemon reloads the pane when a file the page loaded changes, pages get no bridge by default, and --reply grants one call that sends text to the pane that opened the page. In the Agent pane, svg blocks render inline through the mermaid path, and html blocks show code with a Preview toggle that one hidden browser renders as cached images; a click makes that block a live page in place, and Open opens it as a pane. A block opened with html preview shows the picture first and wraps a fragment in a page with the theme colors, which is also what Codex's visualize references become. Replaces the 2026-07-28 userpanes plan.
