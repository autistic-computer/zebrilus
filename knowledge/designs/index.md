# Concepts

* [Accelerated OSR compositing & external begin frames](accelerated-osr-compositing.md) - The plan that replaced the CPU BGRA readback pipeline with CEF shared GPU textures and phase-locked Chromium to zz's frame clock via external BeginFrames; shipped on Linux, macOS, and Windows, with external BeginFrames still unsupported on Windows.
* [Agent accounts by swapping the CLI's own login](agent-account-swap.md) - Claude Code and Codex accounts stop being per-account config folders. Each CLI keeps its one native login and its one native folder; zz parks the logins that are not in use and swaps the chosen one into the native store when no chat of that provider runs. zz remembers who each login is from its own sign-in, never from the CLI's profile cache.
* [Headless agent commands and browser control](agent-backbone-v3.md) - The CLI controls sessions and agent panes. A rendering client owns browser operations and exposes CDP when enabled.
* [Agent chat state and replay](agent-chat-machine.md) - Typed chat events carry turns, items, subagents and requests from provider drivers to client views.
* [Daemon-owned agent runtime](agent-daemon-runtime.md) - The daemon owns agent processes, command queues and transcript replay across client detach.
* [Terminal transcript lens (superseded)](agent-lens.md) - SUPERSEDED: Agent panes replaced the transcript lens on 2026-11-01.
* [Delegating from an agent chat](agent-mentions.md) - The composer can mention a child agent or an existing chat. The daemon retains the parent and routes replies and asks.
* [Shadow terminal for agent panes (superseded)](agent-pane-projection.md) - SUPERSEDED: Agent capture reads chat events directly.
* [Agent turn state](agent-turn-machine.md) - The daemon reconciles prompts, vendor command IDs, late completions and cancellation in the Claude and Codex drivers.
* [Chat mode: chat windows first, the rest piled](chat-mode.md) - The flat sidebar became chat mode: each machine lists its chat windows (a window running Claude Code or Codex) as rows with a face per pane, then folds the windows without a chat into one last row, the pile; a window with two or more panes and the pile open into one-line rows on a track. New chat opens the agent picker with no window behind it, which starts the agent in a chosen folder inside that folder's session. The sidebar view decides what a new pane offers: agents in chat view, pane kinds in the session tree. Desktop, web and iPad share the zz-client model; the HTML client still lists only chat windows.
* [Client core & contract - one brain, every face](client-core-and-contract.md) - Decision record for the shared client contract - protocol-owned commands and keys, sans-IO reduction, typed Agent attention, and a native-shell C ABI.
* [Command stream channel](command-stream-channel.md) - One bounded channel for the caller's standard input and output on a command client: a capped whole read for the sinks that hold their payload, a chunked stream with backpressure for pane input, one byte-preserving carrier on the invocation, and three named sinks, so `source-file -`, `display-message -I`, `split-window -I`, `load-buffer -` and `save-buffer -` share a transport instead of owning five.
* [Daemon performance rebuild](daemon-perf-rebuild.md) - The completed 2026 daemon performance campaign, its measured exit and the original assignments used by the brief generator.
* [Updating the headless CLI and daemon](daemon-update.md) - zz update installs a verified headless binary and restarts the running daemon only when requested.
* [Design system: tone, emphasis and ground](design-system.md) - How zz chrome picks colors and shapes: every filled, tinted or outlined widget names a tone (what it means) and an emphasis (how loud it is), the theme turns the pair into one Paint on the ground it sits on, planes name an elevation, every surface takes its fill, edge, corners and shadow from its surface role, and clippy rejects hand-mixed washes, opacities, borders and shadows outside the kit.
* [Flat sidebar data: pane summaries, attention and time](flat-sidebar-data.md) - The data layer for a flat, two-line-per-window sidebar on every client: one PaneSummary per pane in the tree (last change time, unseen finish latch, last shell command, @name, display cwd and git branch, and the program running in a terminal), one status record for every agent kind, the daemon clock on the handshake, and a renderer-free view model in zz-client. Both data slices are built, and the desktop, web and iPad sidebars draw it when the footer's eye switch is on.
* [One desktop client, multiple daemons](fleet-attach.md) - The desktop tracks each host separately and attaches by host and session.
* [Direct device pairing (retired)](fleet-pairing.md) - The short-code pairing service and its trust registry were retired on 2026-08-01.
* [Floating panes . the popup becomes window-owned](floating-panes.md) - Floating panes as flagged leaves of the window's layout tree, exactly where tmux 3.8 keeps them, with display-popup rebuilt as a modal floating pane the way tmux master 34cd5da4 does it; covers the 3.8 command surface including windows with no tiled pane, the appended v108 wire, sizing, zoom, hit-testing, mouse drags, what each client draws, and the float.core, float.clients and float.keys lanes with their acceptance clauses.
* [Host updates in the app . outdated hosts in the sidebar and Settings](host-update-ui.md) - The desktop app shows which hosts run an older zz and updates them with one click, over ssh or the tailnet. A host is outdated when its running daemon's version is below this app's, read from the facts `zz update --check` already asks for. The app's Update runs the same code as `zz update <host> --restart`, so the owned copy and `restart-server` replace the shell script the app piped over ssh, and tailnet hosts get the offer for the first time. An outdated host carries an arrow in a ring on its sidebar row, and Settings > Hosts is a table with each host's version and Update or Restart beside it. Nothing updates on its own. Built on branch host-update, drawn in the storybook, never run against a real host.
* [Input-reliability audit and hardening plan](input-reliability-audit.md) - The 2026-08-03 four-sweep audit of the bug classes behind the dead-chord field reports . stale-context panics, silent command failures, focus-path listener gaps, strandable pairing state, and stale memo digests . with every confirmed site and the agreed fix order.
* [Interface themes: knobs over one look](interface-themes.md) - The look is penna's one look with a person's knobs over it: accent, tint, corner radius, control shape, glass and UI font, each following the platform's theme file (macos on Apple platforms, default elsewhere) until set. There are no presets to pick and no saved themes; a theme file is the knobs as JSON, and Settings copies the look as one, pastes one in (which sets every knob) or resets them.
* [Layered configuration & native settings view](layered-config-and-settings-view.md) - The decision record behind zz/config, daemon-owned keys crossing the wire, and native settings with split shortcut controls and one-button config import.
* [Multi-device attach . every machine, same session](multi-device-attach.md) - Agreed plan to lift the one-interactive-client-per-session rule so all of the user's devices can attach to one session at once - per-client viewports and window focus, latest-active-wins PTY sizing, presence decorations, and steal-attach falling out for free.
* [Native agent drivers](native-agent-drivers.md) - The daemon's native drivers speak each vendor's own protocol (they drove the Agent pane until it was removed on 2026-10-23). Claude Code runs over stream-json and its control protocol, Codex over a private `codex app-server` per pane, and ACP stays for the agents that speak it natively, all emitting the stream the shared reducer already renders.
* [Native status bar for GUI clients](native-status-bar.md) - The desktop status bar combines the sidebar toggle and left-aligned window pills from structured state while tmux status rows remain a TUI compatibility surface.
* [Shell path picker and which-key](path-picker-and-which-key.md) - The host daemon lists paths for the command palette. The which-key sheet shows bindings for the active key table.
* [PiP panes . every float, thrown to one of nine places](pip-panes.md) - In the GUI clients every floating pane that is not modal draws as a PiP: the pane in a card that casts the float shadow, with the same header as a tiled pane, tile back and zoom in place of the splits. Drag the title to throw it, iOS style, onto one of the nine places move-pane -P names. PiPs on one place fan out so each header shows, and they slide off the side edge, 60 px left showing, while a tiled pane has focus. Underneath it stays a tmux 3.8 float with no new flag, state or wire.
* [Browser egress through an SSH host](remote-browser-egress.md) - On macOS and Linux, a desktop browser pane can resolve names and open connections from its attached SSH host.
* [Adaptive in-flight window for remote attach](remote-flow-window.md) - The daemon limits unacknowledged output so fresh terminal frames can replace queued frames before they enter the network.
* [Remote terminal frames and history](scene-streaming-remote.md) - The retained parts of the 2026 scene-streaming design are local rendering, history backfill and per-pane frame repair.
* [Simulator pane . a booted iOS simulator in a PiP](simulator-pane.md) - A pane kind that shows a booted iOS simulator's screen and takes touches and keys. It opens as a PiP at centre-right and docks with Tile back like any pane. The desktop client on macOS does the work; the daemon only keeps the pane's device. The kind travels as `Other { kind }` with a gated descriptor event, so the wire epoch stays.
* [Split updates . the client and the daemon update apart](split-updates.md) - Plan to let a client update without restarting the daemon and ending its sessions. PROTOCOL_VERSION becomes a wire epoch that only bumps for changes an existing peer cannot decode or would get wrong, additive changes travel as messages gated by the capabilities both hellos already carry, a build revision on each side sets floors for behavior, and restarting the daemon onto a newer build becomes its own action that states how many sessions it ends. All four steps are built: the setup epoch (v123), the capability rule, the client UI, and the macOS pty helper pinned to the daemon's build; the desktop app now installs an update itself and restarts into it without ending the sessions.
* [Per-theme surface recipes (superseded)](surface-roles.md) - SUPERSEDED: penna owns the recipes for surfaces and controls.
* [Tailnet hosts](tailnet-node.md) - Discovery, peer admission, native clients and an optional daemon-owned Tailscale node.
* [Terminal bell . Ghostty-parity notifications](terminal-bell.md) - Shipped plan to stop swallowing BEL - register libghostty's on_bell in the daemon, carry a per-pane bell flag in mux state and the snapshot plus an appended EventPayload edge event, badge the pane's sidebar icon, render a `!` window flag, request window attention and play the macOS system beep on the ring edge, clear on pane input, selection, or window activation; no OS notification popup, no config in v1.
* [tmux drop-in campaign](tmux-drop-in.md) - The original compatibility campaign covered configs, shell use, control mode and terminal attach.
* [tmux compatibility and zz-specific commands](tmux-superset-roadmap.md) - Compatibility decisions, scope and evidence for the alias campaign and the subsequent 3.8 catch-up.
* [TUI client - zz in a terminal, browsers included](tui-client.md) - A second presentation backend that renders zz sessions in a raw TTY - cell blit for terminals, text views for agents, kitty-graphics CEF frames for browsers - turning the GUI into one of three faces of the daemon.
* [Per-pane TUI customize mode](tui-customize-mode.md) - Port mode-tree.c and window-customize.c onto the server pane mode stack, and share one prompt editor between customize-mode and switch-mode.
* [TUI parity campaign](tui-parity.md) - The terminal-client parity contract: tmux observable behavior by default, zz additions through superset commands, and proof tied to the tested revision.
* [HTML pages and inline chat previews](userpanes.md) - The daemon serves HTML files to browser panes. Desktop, iOS and web also render inline chat previews.
