# Update Log

## 2026-11-27

* zz-ui's chat view `agent/chat.rs` now holds its types, `chat_surface`, the thread drawing and every row that carries an element id; the `ChatPane` methods, thread rows, draw hooks, markdown cache, child peek lines, peer row helpers and agent tiles moved into subject files under `crates/zz-ui/src/agent/chat/`, and its tests into thread, image and render test files beside them. The test-only views stay inline so their type paths do not change. The target picker's ranking and item building moved from `target.rs` into `target/items.rs`. [Agent panes](/concepts/agent-panes.md) and the [palette](/concepts/command-palette.md) name the new files.
* Tests moved out of the client core's `core.rs`, the raw TUI's `app.rs` and `input.rs`, the terminal crate's `appearance.rs` and the mux crate's `layout.rs` into subject test files beside them, and the daemon's `ctrl_tests.rs` split into `ctrl_<subject>_tests.rs` files. The mux layout presets moved into `layout/presets.rs`, and customize mode's rows, drawing, input and editing into subject files under `crates/zz-mux/src/command/customize/`. The [zz-client](/crates/zz-client.md), [zz-mux](/crates/zz-mux.md), [zz-terminal](/crates/zz-terminal.md) and [zz-daemon](/crates/zz-daemon.md) pages and the [TUI client](/designs/tui-client.md) list the files.
* The agent crate's `fanout.rs`, `host.rs`, `claude/mod.rs` and `codex/mod.rs` moved their tests into subject test files beside them, and Codex approval and question handling moved into `codex/approvals.rs`. The daemon client's `client.rs` now holds the client types, the protocol sender and receiver and the handshake; the `CommandClient` methods moved into `client/command.rs` and the `InteractiveClient` methods into `client/interactive.rs`. Its `endpoint.rs` moved its tests into `endpoint/parse_tests.rs` and `endpoint/ssh_tests.rs`, and the Windows ssh forward into `endpoint/windows_forward.rs`. The [zz-agent](/crates/zz-agent.md) and [zz-daemon-client](/crates/zz-daemon-client.md) pages list the files, and pages that named `client.rs` for moved code point at the new files.
* The CLI crate's `lib.rs` now holds the crate root types, shared constants and the module declarations; startup and application arguments, command mode, help, native attach, output, kill-server, daemon spawn, launcher defaults and host targeting moved into subject files beside it, re-exported so every public path still resolves. Its tests and those of `control_mode.rs` moved into subject test files, and the `cli_binary` integration test became the `tests/cli_binary/` directory, still one binary, with one file per module. The [zz-cli](/crates/zz-cli.md) page lists the files, and pages that named `lib.rs` for moved code point at the new files.
* The daemon's `status.rs` now holds the status types whose fields several files share, the context format lists and cycle frame tracking; the renderer, format hooks, format facts, status parts, mode and theme formats, terminfo and the shell job cache moved into subject files under `crates/zz-daemon/src/status/`, and the status tests into subject test files beside them, `format_status_tests.rs` included. The [zz-daemon](/crates/zz-daemon.md) page lists the files, and pages that named `status.rs` for moved code point at the new files.
* zz-ui's `terminal.rs` now holds the painter's types, `RowRenderCache` and the find bar; the look and contrast, text shaping, box drawing, selection and overlays, cursor, metrics, scrollbar and kitty image helpers moved into subject files under `crates/zz-ui/src/terminal/`. The raw TUI's `render.rs` now holds `Renderer`, its state and frame plumbing; the workspace, terminal pane, status, sidebar, menu, chooser and cursor drawing and the SGR and colour writers moved into subject files under `crates/zz-tui/src/render/`. Both sets of tests moved into subject test files beside them. [Terminal painting](/terminal/rendering-parity.md) and the [TUI client](/designs/tui-client.md) list the files.
* The desktop app's `workspace/view.rs` now holds `AppView`, its state types, `AppView::new` and its render; the key handling, palettes, focus, pane synchronization, agents, drags, pane content, layout, floating panes and overlays moved into subject files under `crates/zz/src/workspace/view/`. `mux/client.rs` now holds `MuxClient`, its types, constructors, accessors and event emitters; connections, daemon restarts, overlay state, input, commands, providers, attach, images, agent streams, messages and history moved into subject files under `crates/zz/src/mux/client/`. Both sets of tests moved into subject test files beside them. The [zz](/crates/zz.md) page lists the files, and pages that named either file for moved code point at the new files.

## 2026-11-26
* **Creation**: Proposed the [English to command translator](/designs/english-command-translator.md): a small local model that turns an English sentence and the current session's state into zz commands and runs them with no preview. Nothing is built.

* The mux crate's `command.rs` now holds the engine's core types, the dispatch `match`, alias resolution and shared helpers; each command family moved into a subject file under `crates/zz-mux/src/command/`, and its tests into subject test files beside them. The [zz-mux](/crates/zz-mux.md) page lists the files, and the [command set](/tmux/commands.md) maps every command name, engine or daemon, to the file that runs it.
* The daemon's `daemon.rs` now holds only the core state, the `Daemon` entry point and shared helpers; the `Shared` methods moved into subject files under `daemon/`, and effect application split into per-subject helpers and named post-lock drain steps. The [zz-daemon](/crates/zz-daemon.md) page is now a map of the request flow, the `ServerState` layout and the file that owns each concern, and [daemon lock order](/architecture/daemon-locks.md) records which mutexes come before and after `inner`. Pages that named `daemon.rs` for moved code point at the new files.
* The mux crate's `model.rs` and `formats.rs` now hold their types and entry points; the `MuxState` methods moved into subject files under `crates/zz-mux/src/model/` and format expansion into subject files under `crates/zz-mux/src/formats/`, each with its tests in a subject test file beside it. The [zz-mux](/crates/zz-mux.md) page lists the files, and pages that named `model.rs` or `formats.rs` for moved code point at the new files.
* The terminal crate's `session.rs` now holds the public session types, guards and shared struct definitions; the `TerminalSession` methods, actor channels, engine filter, view state, publisher, view actions, capture, copy mode, search, snapshots, frames, input encoding, PTY I/O and the Linux gather stage moved into subject files under `crates/zz-terminal/src/session/`, and its tests into subject test files beside them. The [zz-terminal](/crates/zz-terminal.md) page lists the files, and pages that named `session.rs` for moved code point at the new files.
* The protocol crate's `message.rs` now holds `ProtocolMessage`, `EventPayload`, the epoch and revision constants and the decoders only those enums use; the other wire types moved into subject files under `crates/zz-protocol/src/message/`, re-exported so every path still resolves, and its tests into `message_tests.rs`. The wire check in `compat/wire-version.py` now compares items across all protocol files, so a move between files is not a wire change while an edited, added, removed or reordered field or variant still is. The [zz-protocol](/crates/zz-protocol.md) page lists the files and the [wire protocol](/protocol/wire-protocol.md) page says what the check compares.

## 2026-11-25

* The desktop app marks hosts on an older zz and updates them on request. An outdated host carries an arrow in a ring on its sidebar row, and Settings › Hosts is a table with each host's version and Update or Restart. The dialog that opened on connect is gone. See [host updates in the app](/designs/host-update-ui.md).
* Chat view lists every machine and puts New chat on a machine's header. On the desktop the New chat screen has a target machine and attaches nothing until an agent is picked, and a picker pane offers the agents and the pane kinds in both sidebar views. See [chat mode](/designs/chat-mode.md).
