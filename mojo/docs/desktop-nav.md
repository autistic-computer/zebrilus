# Desktop navigation command boundary

The desktop's `mux::nav` target activation and command helpers delegate to `zz_client::desktop_nav`, and `MuxTreeModel`'s per-node queries delegate to `zz_client::desktop_fleet`. `NavActivation<Host>` keeps the desktop's host type; no host ids are converted or reordered at the Rust call sites. MuxClient's new-session helper and AppShell's detach command use the same renderer-free source.

`desktop_nav.mojo` keeps the typed target and activation results. `NavActivation.kind` follows the source enum: 0 attach to another host, 1 attach a session, 2 attach at a `$session:@window[.%pane]` target, 3 execute commands, 4 attach then execute, 5 reconnect. A disconnected target produces no activation. A non-session target on another host or another session uses the owner session/window target; a missing owner window refuses activation. Without an owner session the source still produces a direct execute result, and the frontend keeps that rather than adding existence checks to this helper.

Direct pane selection sends `select-window -t %pane` followed by `select-pane -t %pane`. Picker splits keep `--kind picker`, the axis flag and the pane target. New-window and kill commands keep their typed identifier prefixes. Global Detach runs `detach-client`, distinct from MuxClient shutdown. Rename runs `command-prompt -p "rename-session: " -I <name> "rename-session -t '$id' -- '%%'"` (or the window form) under the menu label "Rename Session…" or "Rename Window…"; on another host it attaches to the owner session first. These requests keep default source, block, alias and stdin fields and compare with the protocol encoder.

Local new-session creation uses the supplied working directory and adds an explicit attach only when the `new-session-attach-v1` capability is absent. Remote creation stays detached and ignores directory and capability payloads. The working directory is chosen by the caller: `DesktopSidebar.new_session` passes it only for the local host with a loaded, empty snapshot, and the shell supplies a current directory that exists. Lossy path conversion matches the source, including the invalid-UTF-8 path case on Linux.

The boundary keeps the 4 MiB command limit and admits at most 4,096 capability strings and 64 KiB of capability text for local creation. It refuses invalid target kinds, axes, rename targets and oversized local requests before publishing a queue effect. Ignored remote payloads are not cloned.

Publication goes through `desktop_sidebar.stage_navigation` and `commit_navigation` (see `desktop-sidebar.md`): one staged batch per activation on the attached host, committed only for the same source and queue generation, and a `host_request` for anything that needs another host's connection.

Run `python3 mojo/scripts/desktop_nav_vectors.py`. It compares 6,912 delegated activation results, 64 new-session cases and 25 direct command batches: 258,748 bytes plus exact command frames. Rename prompts, host activations and attach-then-execute results are compared through `desktop_fleet_vectors.py`.
