# Desktop navigation command boundary

The actual desktop's `mux::nav` target activation and command helpers now delegate to `zz_client::desktop_nav`. Its `NavActivation<Host>` preserves the desktop's existing host type; no host IDs are converted or reordered at the Rust call sites. MuxClient's new-session helper and AppShell's detach command use the same renderer-free source implementation. This extraction changes no GUI route or command queue behavior.

`desktop_nav.mojo` preserves the corresponding typed target and activation results. A disconnected target produces no activation. A non-session target on another host or attached session uses the owner session/window attach target; a missing required owner window refuses activation. Without an owner session, the source can still produce a direct execute result. The frontend must preserve that behavior rather than add target-existence assumptions to this low-level helper.

Direct pane selection sends `select-window -t %pane` followed by `select-pane -t %pane`. Picker splits retain `--kind picker`, the original axis flag and the authoritative pane target. New-window and kill commands keep their typed identifier prefixes. Global Detach runs `detach-client`; it is distinct from the MuxClient shutdown method. These command requests retain default source/block/alias/stdin fields and compare with the actual protocol encoder.

Local new-session creation uses the supplied working directory and adds an explicit attach only when the source capability is absent. Remote creation stays detached and ignores working-directory/capability payloads. The actual caller's choice of working directory still requires a known empty local snapshot and a valid current directory; the pure helper does not perform that filesystem policy. Lossy path conversion matches the source before command construction, including the checked invalid-UTF8 path case on Linux.

The Mojo boundary retains the existing 4 MiB command limit and admits at most 4,096 capability strings/64 KiB of capability text for local creation. It refuses invalid target kinds/axes and oversized local requests before publishing any queue effect. Ignored remote payloads are not cloned. These are explicit admission limits, separate from source command semantics.

Run `python3 mojo/scripts/desktop_nav_vectors.py`. It compares 6,912 actual delegated activation results, 64 new-session cases and 25 direct command batches: 258,748 normalized bytes plus exact native command frames. The source reference run peaked at 665 MiB, the focused source/Mojo differential at 276 MiB, scoped source clippy at 393 MiB, and the actual desktop check at 916 MiB with the existing platform-unused traffic-light warning. Fleet projection, sidebar state and the staged global action consumer remain the next layer; this checkpoint does not enable a live shortcut hook.
