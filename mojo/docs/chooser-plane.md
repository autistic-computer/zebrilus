# Retained chooser presentation

`chooser_plane_protocol` decodes the actual `ChooserPresentation` event, including all five preview variants: Tiles, Screen, Text, Client and Markup. It retains row names/text/alignment, all style strings, sort/view/filter, preview size and current tile, prompt cursor colour/style/column/line, client status data and complete nested packed terminal viewports. This metadata remains source data; unused terminal presentation fields do not become new GUI styling rules.

`differential-chooser-plane` compares 1,629 actual Rust decoder cases and 43,130,135 fixture bytes: 822 accepted, 800 malformed rejected, two unrelated messages ignored and five explicit resource refusals. The corpus includes nested viewport corruption, Unicode/NUL, every preview, cursor colours, maximum numeric values, row/text/viewport limits and compressed grids that expand beyond the aggregate cell budget. Outer trailing postcard bytes are accepted as in the source; packed viewport bodies enforce their own complete-consumption rule.

The decoder bounds each text at 1 MiB, each collection at 65,536 entries and all collections together at 131,072 entries. Text plus nested encoded viewport bytes cannot exceed 32 MiB. A presentation may retain at most 256 viewports and 8,388,608 cells in total. A conservative 64 MiB retained-storage budget charges vector capacities, cells/styles/dictionaries/overlays/image placements and strings. Grid dimensions are charged before decoding their compressed rows. One bounded viewport may be transiently decoded before its full storage charge is known; a rejected event never replaces retained state.

`chooser_buffer_protocol` also consumes typed Buffer state and updates, retaining name, preview, size/time, key/text/tagged, search, selection, filter, help and prompt. Its 865 actual decoder cases include 354 accepted, 508 malformed rejected and three explicit resource refusals. Source key/text bounds remain 64/512 bytes; additional frontend bounds are 65,536 rows, 1 MiB per other string and 32 MiB aggregate text. Source-accepted outer trailing bytes remain accepted.

`PaletteDialogs` shares immutable presentation and Buffer item allocations across `StreamModel` and `AppModel`. Tree/Buffer replacements clear the presentation; updates preserve it. A presentation event advances the active Tree revision first, otherwise the active Buffer revision, and still retains metadata when neither is active. Revisions wrap from maximum to one. The GUI uses the extracted Rust revision helper too. The Tree closed watermark follows the source's final state when a protocol Batch completes, including close-and-reopen batches.

`differential-chooser-retention` checks 591 actual `ClientCore`/GUI-revision transitions through the pure reducer, the real idle `InteractiveConnection.consume` with the compiled Bend envelope gate, and `AppModel.refresh`: 129,801 exact summary bytes. It tests zero/maximum revisions, mixed Tree/Buffer presence and batches. Session or attachment-generation changes clear retained dialogs with source present-only revision bumps; ServerStopping uses the GUI's unconditional reset. A separate stress assertion preserves the same 65,536 Buffer rows and 1 MiB presentation text allocation across 10,000 updates and snapshots. The existing 197 prompt/Tree retention cases also remain green. The expanded check peaked at 1,296 MiB under the shared 4 GiB guard.

This typed retention checkpoint does not enable `client-native-chooser-v1`. Panes/Clients live routing, the distinct Windows palette mode and Buffer frontend behavior must all be ready before the default app advertises that capability.
