# Remaining desktop app migration

This inventory follows actual desktop source modules and current Mojo imports/call sites. A checked leaf or retained protocol field is distinct from a live frontend consumer. The router's machine-checked laws remain kernel and transaction claims; finite source, GPU and daemon checks establish their documented boundaries.

| Source behavior | Current Mojo path | Remaining integration |
| --- | --- | --- |
| Mux stream, tree/view reduction, retained terminal patches | `stream_transport`, `tree_gate`, `terminal_model`, shared Bend worker | Continue source-specific event consumers; unknown events retain the explicit 4 MiB refusal boundary. |
| Terminal painting, history/local scrolling, search, copy/paste/PRIMARY, IME and command output | `view`, terminal painters, local-scroll/search/clipboard/pointer controllers and ordered input timeline | Configured terminal actions and native font offsets must replace stock shortcut decisions through the checked complete-map adapter. |
| Desktop global routing and configured keymaps | `desktop_workspace`, checked Bend input gate, full key-table retention, configuration parser and native registry | The live workspace resolves only the configured `ui` table for key presses (window shortcuts, global commands, sidebar toggle) ahead of terminal forwarding, as the router does. Materialize the remaining global intents, join configured/native install receipts, preserve native pending/replay and publish at original input markers with fresh source/target checks. |
| Native Panes/Clients chooser | `chooser_live`, `chooser_session`, `view` and backend; `WindowChooserRuntime` in `window_chooser_runtime` live in `WorkspaceView` for the Windows chooser (ordered input, composition, wheel, paint, return to the local palette), checked by `window-chooser-workspace-smoke` | Experimental capability stays off by default (`zz-mojo-app --native-chooser` turns it on). Buffer uses the shared typed plane and checked leaf foundations but needs complete live controller/frontend activation. |
| WhichKey | Checked model, native widget/layout leaves, the timer policy (4,052 cases) and `LiveWhichKey`, wired into `WorkspaceView` for key presses, key-table changes and the per-frame sheet | The all-keys intent needs `DesktopWorkspace` to route live keys and acknowledge its kind 3 effect; until then the all-keys key goes to the daemon. |
| Command palette and path picker | `palette_runtime`, component/controller, files adapter and background rank worker | Preserve existing live ordering while adding the remaining app surfaces; no synchronous ranking in View. |
| Browser tabs, navigation and native host | `BrowserPane` in `browser_pane`, proven live on the real engine by `mojo/scripts/browser_pane_check.py` | `WorkspaceView.terminals` still has no browser dispatch. Follow the wiring steps at the end of `browser.md`. |
| Sidebar fleet tree, expansion/navigation, rename and nine window shortcuts | `DesktopSidebar` live in `WorkspaceView`: the left panel draws its rows for the local daemon (state, Welcome platform, snapshot), row and disclosure clicks, wheel scroll, and the configured `ui` table's window shortcuts and global commands through `stage_navigation`/`commit_navigation`; checked by `sidebar-workspace-smoke` on a private daemon | Sidebar keyboard focus and the `sidebar` table, rename menu, row hover buttons, agent badges, host install/remove menu actions, the flat chat list and the shortcut overlay. |
| New session/window, picker splits, detach and local routes | Toolbar buttons and `ui` keys stage the sidebar's command batches; the backend's own session and split actions are gone. Picker panes draw their choices and run `select-pane-kind` or `kill-pane` like the source picker | Activations for other hosts come back as `host_request` until the backend holds more than one daemon connection. The rest of the global router (held keys, `terminal`/`sidebar` tables, prefix chrome keys with their cancel) is not live. |
| Editor pane and file picker | Generic mjui text/editor facilities; `editor_pointer` serves current text fields | No editor-pane controller or View branch. Port descriptor/pending-path synchronization, bounded 8 MiB local open/save, dirty/saved state, retry, title and file-picker lifecycle. |
| Agent controller, transcript/chat, prompts, permissions and settings | Terminal/agent metadata survives generic tree snapshots; no agent pane controller imported by View | Port typed bounded agent event consumption and actual transcript/business state, then composer, queued prompt, permission/question/settings and attachment flows. Avoid treating raw retained events as completed consumers. |
| Settings/configuration/import/watch | Appearance, font policy and complete keyboard configuration leaves; CLI config parsing | No desktop settings route/component. Port settings state, validated daemon option/key changes, local persistence/watch/import and preview/commit/rollback policy. |
| Native shell/status/pane controls, hosts/SSH/install/tray/update | Basic native window and terminal workspace; palette owns notifications | App-window composition remains root-owned. Remaining shell, fleet connection prompts, pane-kind dispatch, controls and desktop host features need actual Source adapters and UI integration. |

The sidebar fleet controller (`desktop_sidebar.mojo`, see `desktop-sidebar.md`) is live in `WorkspaceView` with the router's command batches and window shortcuts; `WindowChooserRuntime` is live behind the chooser capability; `BrowserPane` has its wiring steps at the end of its page. Buffer and shell composition stay with root. Editor and agent remain explicit subsequent app-controller work.

Source entry points are `crates/zz/src/workspace/{view,sidebar}.rs`, `mux/client.rs`, `editor/view.rs`, `agent/{controller,view}.rs`, `config/settings.rs`, `browser/{controller,view}.rs` and `ui_scale.rs`. Current live dispatch is in `mojo/zzmojo/{view,backend,workspace_keys,input_timeline,stream_transport}.mojo`; the generic pane renderer's fallback still says “Connecting to terminal…” for a pane without terminal data.
