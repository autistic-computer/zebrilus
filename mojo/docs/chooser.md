The tree chooser presentation consumes the existing typed `ChooseSnapshot` and keeps its immutable row allocation shared. `ChooserPresentation` computes the source title, subtitle, requested modal height and key-gutter policy once; `row(index)` projects only the requested row. It preserves the daemon's initial selected value, including an out-of-range value, rather than manufacturing a selected row.

Rows preserve the source target prefixes and full unsigned identifiers, indentation depth, disclosure flags, active/tagged state and optional pane kind. A nonempty custom format replaces the complete label/detail pair. Hidden original labels and details are not shaped or rejected by display limits when that override applies. Search presentation preserves its forward/reverse prefix and appends marked composition to the daemon query. Native search-key ownership uses the existing typed modifier flags: ordinary character input belongs to the text system while searching; Control, Alt and platform combinations remain key actions.

`python3 mojo/scripts/chooser_presentation_vectors.py` runs the actual Rust helpers now used by the native chooser GUI. It compares 170 encoded source states, 9,290 rows and all 64 character/search/modifier combinations: 628,274 exact output bytes. The corpus covers every flag byte, zero/maximum identifiers for all four target kinds, Unicode and NUL text, custom formats, optional pane kinds, empty lists, both search directions, help/prompt combinations and row counts above the ten-row visual cap. The probe also checks that presentation shares the source row allocation and that oversized display/composition input is refused without changing retained state.

The existing 65,536-row and 32 MiB protocol limits remain. Displayed labels/details and search-plus-composition have a separate 64 KiB shaping limit; custom formats retain the 512-byte protocol limit and shortcut keys retain 64 bytes. The first reference/Mojo build peaked at 1,262 MiB, the final differential at 284 MiB and scoped Rust clippy at 122/385 MiB, all under the shared guard.

`chooser_component.render_chooser` builds the standalone native scene from that retained presentation. It returns typed logical panel/list viewport bounds and selection, activation and close intents. It accepts a positive scroll offset and marked composition, projects at most twelve rows, and validates displayed row/composition bounds before painting. The source line-wrapper truncation helper reshapes each returned prefix and ellipsis together; its independent check covers 7,308 native strings and 588 exact scalar widths, including font fallbacks and control characters.

`measure_chooser` returns the same panel, viewport, notice heights and row height before painting or interaction. The live list can therefore apply its source non-strict centering on the first frame. Its wheel line-height metadata retains the inherited default Body value of 18 logical pixels. A trailing `overlay=False` renderer option keeps the component inside an existing managed modal layer; the default standalone overlay remains available.

`python3 mojo/scripts/chooser_scene_pixels.py` captures the actual native `ChooserModal` and `tree_chooser_row` with all six built-in themes at 1, 1.25 and 2 device scale. The reference matrix includes ordinary rows, active/disclosed/tagged/selected states, a selected badge, custom formats, forward/reverse search, help and prompt notices, empty clients, a small vertical viewport, and a narrow keyless list with full unsigned identifiers. It also covers a wrapped seven-line prompt with help and a long reverse-search query. The source captures contain 83,349,000 pixels across 126 scenes. The comparison reports exact pixel counts independently of the reference capture report.

The modal is concentric with its 40px rows: its corner is the control corner of a row plus the 8px inset. A theme whose floating surfaces carry a hairline rim (the bordered Yaru pair) lays the header, notices, list and footer inside that rim, and the list keeps at least its 8px padding above and below, so a short modal overflows into the footer as the source does. 84 of the 126 scenes match exactly. The other 42 are the two pill-control themes, where 2 pixels per scene (4 at scale 2) differ, 112 in all, with a channel error of at most 6: the two ends of the footer's top rule. There the source clips the rule to the panel's grown, smoothed corner, which reaches the rule's row, while mjui's rounded clip uses the plain corner radius. The candidate build peaked at 1,051 MiB; the complete render-only comparison peaked at 250 MiB under the shared guard. Intrinsic text/icon line boxes retain their source height until device conversion, footer content includes the top border in its layout, and source-compatible icon bounds accumulate parent coordinates in physical units. Notice measurement uses the actual wrapped paragraph height, preserving the fixed requested modal height while reducing the list viewport.

The live desktop uses this modal for Panes and Clients; Windows uses the command palette's separate window-chooser mode. Retained pointer/key routing, IME ownership and live daemon actions require their own integration checks before the GUI advertises native chooser support. The source capability also gates the buffer chooser, whose frontend remains a separate integration requirement.
