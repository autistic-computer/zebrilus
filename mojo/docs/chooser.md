The tree chooser presentation consumes the existing typed `ChooseSnapshot` and keeps its immutable row allocation shared. `ChooserPresentation` computes the source title, subtitle, requested modal height and key-gutter policy once; `row(index)` projects only the requested row. It preserves the daemon's initial selected value, including an out-of-range value, rather than manufacturing a selected row.

Rows preserve the source target prefixes and full unsigned identifiers, indentation depth, disclosure flags, active/tagged state and optional pane kind. A nonempty custom format replaces the complete label/detail pair. Hidden original labels and details are not shaped or rejected by display limits when that override applies. Search presentation preserves its forward/reverse prefix and appends marked composition to the daemon query. Native search-key ownership uses the existing typed modifier flags: ordinary character input belongs to the text system while searching; Control, Alt and platform combinations remain key actions.

`python3 mojo/scripts/chooser_presentation_vectors.py` runs the actual Rust helpers now used by the native chooser GUI. It compares 170 encoded source states, 9,290 rows and all 64 character/search/modifier combinations: 628,274 exact output bytes. The corpus covers every flag byte, zero/maximum identifiers for all four target kinds, Unicode and NUL text, custom formats, optional pane kinds, empty lists, both search directions, help/prompt combinations and row counts above the ten-row visual cap. The probe also checks that presentation shares the source row allocation and that oversized display/composition input is refused without changing retained state.

The existing 65,536-row and 32 MiB protocol limits remain. Displayed labels/details and search-plus-composition have a separate 64 KiB shaping limit; custom formats retain the 512-byte protocol limit and shortcut keys retain 64 bytes. The first reference/Mojo build peaked at 1,262 MiB, the final differential at 284 MiB and scoped Rust clippy at 122/385 MiB, all under the shared guard.

This establishes the presentation and input-policy foundation. Native chooser rendering, retained pointer/key routing, IME ownership and live daemon actions still need their own integration checks.
