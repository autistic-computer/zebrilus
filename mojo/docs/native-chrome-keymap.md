# Native Chrome binding boundary

`DesktopNativeKeymap` ports the desktop's native binding installation and the relevant framework lookup behavior. The actual `zz::keymap` install, bound/dropped snapshots and chord projection now delegate to renderer-free `zz_config::keymap` helpers. Actual terminal, sidebar, browser and root UI binding builders delegate to the surface enums. The actual terminal's two raw Tab suppressors share the source constants used by the oracle.

Installation follows the desktop's registration order: root UI, browser, terminal, sidebar. The initial terminal raw bindings precede its configured bindings. Terminal configured chords retain the stable platform-modifier-first partition. Subsequent configuration notifications use registration order through the framework's ordered subscriber set. Removed keys are calculated from the previous complete bound map; changing the action on a still-present key does not count as removal.

The framework appends bindings. An unsupported cross-family replacement emits no new native callback and can leave an earlier callback active. Removing that unsupported replacement can likewise leave the earlier callback, because its dropped action remains unsupported by that builder. Removing a supported binding emits NoAction. The registry retains this history, typed indexed actions and original chord strings; it does not reconstruct native callbacks from only the current map.

`NativeKeystroke` retains key, modifier bits, Fn and optional character alternative. Its parser follows actual Ala parsing, including accepted empty key strings and character alternatives that the renderer-free configuration parser deliberately discards. Lookup preserves alternative-character modifier handling, exact matching, target-depth precedence, reverse installation order, NoAction suppression and pending-sequence identity/removal. Queries cover terminal/sidebar/browser beneath the root, root alone and no relevant context. Other widget contexts and arbitrary predicate/meta/Unbind extensions are outside this projected boundary.

Each install prepares complete private records and its new bound snapshot. Publication checks both the monotonic registry generation and current map version before no-allocation swaps. A stale query refuses resolution after installation. The enclosing app coordinator still needs to join this publication with its router-map receipt and drained delivery; this module does not enable an app hook or manage framework input timeout/replay. Prepared key delivery must still validate fresh source, focus, target and epoch before consuming native results.

Admission limits are separate from source semantics: 4,096 retained records, a conservative 2 MiB budget including record/stroke/string storage, 32 strokes per sequence or query, and 64 KiB query/parser text. A map is admitted through the existing complete map's 4,096-binding/1 MiB boundary. Long or over-budget installs refuse as a whole without changing the published generation, records or bound map. The capacity check reaches 4,089 published records and 1,633,898 conservatively accounted bytes; the following complete install refuses instead of publishing a prefix. Input and output lists remain bounded; raw payload arenas and action queues keep their existing independent limits.

The actual root UI zoom handlers delegate percentage conversion to the same source module. `DesktopUiZoom` preserves 50–300 percent clamping, ten-percentage-point changes, reset and exact Float32 order. Its public boundary explicitly refuses nonfinite percentages. Host/window scale application is not connected by this checkpoint.

Run `python3 mojo/scripts/native_chrome_keymap_vectors.py`. The actual framework oracle checks 144 parses, 72 installations across three complete profiles, 3,703 emitted records, 8,280 ordered matching/pending queries and 1,024 zoom transitions, represented by 242,982 normalized bytes. The corpus includes Fn, alternative characters, zero-length queries, Unicode whitespace sequences, removed keys, cross-family replacements and raw Tab suppression. It also checks stale map/query receipts, capacity refusal, a 33-stroke install, exhausted counters and nonfinite zoom refusal.

The final source clippy, actual desktop check, complete differential and runtime profile pass under the shared one-job 4 GiB guard, peaking at 1,764 MiB. The standalone corpus and refusal checks take 0.11 seconds and 12,712 KiB maximum RSS on the tested Linux host. The platform profile vectors do not establish native macOS or Windows execution. These finite results add no universal source-equivalence or new Bend proof claim; live interception remains disabled.
