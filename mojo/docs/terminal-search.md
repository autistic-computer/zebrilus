# Terminal search and copy commands

`terminal_search_protocol.mojo` encodes the full terminal search query and all 76 copy-mode actions, including counted commands and clipboard/buffer/pipe copy options. Ordinary terminal actions carry a pane ID; command-output actions use their separate pane-free wire variant. The decoder accepts the actual `TerminalUiCommand` event variant (8) and preserves search direction.

`terminal_search.mojo` ports the source search helper and prompt behavior. Keyboard Alt-C cycles smart, sensitive and insensitive case; the native case button toggles sensitive and insensitive. Enter advances according to direction XOR Shift. A daemon-requested accept prompt closes locally on Enter without sending `SearchClose`, and consumes the physical closing key until its release. These distinct source behaviors are retained.

`terminal_search_editor.mojo` keeps the editable query and controller synchronized after each individual input event. Text, paste and repeated navigation retain their order. Its result reports the number of consumed text events, so a caller can restore terminal focus and forward only the suffix after a closing command. The clipboard value adapter reads the host only for an actual paste or PRIMARY gesture; writes immediately update its own value and are delivered to the host afterward.

`terminal_search_chrome.mojo` draws the native source's 460-pixel wrapping popover, 110-pixel minimum field, regular 28-pixel input, 24-pixel flat icon buttons, status caption, tooltips and case/regex current states. The field prefix uses the font's cap-height alignment. Compact buttons retain the source's 18-pixel glyph and half-pixel drop. Navigation is disabled for absent, empty, pending or invalid results. `terminal_mode_indicator.mojo` preserves copy/view labels, hidden positions and unseen-output counts.

`terminal_search_controller.mojo` keeps ordinary pane and command-output owners distinct. It retires state on source identity changes, pane removal and output replacement. Query text and composition each have a 1 MiB limit, undo payloads have a 4 MiB/64-edit limit, and all retained editors share an 8 MiB budget with at most 512 entries. The budget counts list capacities, reserves twice the query's UTF-8 length and retains a conservative 4 KiB metadata charge per peak entry until source retirement. Evicting a cold open editor returns a passive `SearchClose` without moving focus. A frame retains fewer than 4 MiB of encoded changes and handles at most 4,096 input events. Rejected excess query input stays in the search field's input domain and sets the result's `limited` flag. These explicit resource limits extend the otherwise unbounded source behavior.

The source oracle invokes the real Rust serializer and public client helpers. It checks every copy-mode variant, boundary payloads, query combinations, forward/backward UI events, keyboard modifiers, case labels, server search status and full mode-indicator text. Focused component checks cover event ordering, copy-before-paste behavior, prompt closing, physical key release swallowing, ordinary/output identity, source retirement, clipboard read gating and cross-pane eviction. This is source differential and executable UI evidence; it adds no universal formal verification claim.

The initial checkpoint passes 9,916 source cases and 128,159 exact result bytes. The private daemon check confirms two sensitive and three smart-case matches, next/previous convergence, invalid regex, hidden copy-mode positions, accepting without a close frame, return to live mode and PTY input isolation with Bend tree/cell execution active. The six-pane, 1 MiB-query controller test measured 25,600 KiB peak native RSS. All checks run through the shared 4 GiB memory guard.

Run `python3 mojo/scripts/search_vectors.py`, `python3 mojo/scripts/search_checks.py`, `python3 mojo/scripts/search_checks.py --ui` and `python3 mojo/scripts/search_smoke.py` from the repository root. The UI check writes `target/port/terminal-search-chrome.png`.

## Integration API

Prepare only editors that are opened, using `TerminalSearchController.ensure(target, keys, style)`. `SearchTarget(pane, command_output, owner)` uses the pane as an ordinary owner and the actual command-output ID for an output owner. Each target needs eight stable widget keys in `SearchKeys`.

`begin(target, direction, behavior)` and `route_key(...)` return `SearchEffect`: send its frame to the captured target, apply `cancel_scroll` before sending, clear host composition when requested, and move focus only when `focus` is nonzero. A search focus points to `SearchKeys.field`; terminal focus uses the existing terminal focus key. Preserve output parking and ordinary input selection epochs.

Before ordinary text forwarding, call `SearchEditor.update(ui, input, clipboard, pane, command_output)` for the focused field, deliver its effects in order, and begin terminal forwarding at `result.consumed` if the prompt closed. Render with `build_search_chrome(...)`; it returns the same ordered effect collection for toolbar actions. `target_for_field` resolves editor focus and `owns_key` occludes search pointer/wheel gestures from the terminal underneath.

The live input timeline must dispatch search edits in the same sequence as ordinary text, clipboard and captured raw keys. A physical Find or Alt-toggle may update local focus immediately, but its wire frame belongs at its captured input-event position. Integrating the editor therefore requires a pointer/composition preparation phase and individual event dispatch inside the timeline; processing all search changes before older pending terminal keys would reorder input. The standalone component's complete-frame API remains useful for private scenes and focused checks.

Call `observe(server, client, valid_targets)` when source/pane/output ownership changes and `enforce(protected_name)` after edits. Apply returned eviction frames passively to their captured targets. Drain decoded search UI commands once from a UI-owned backend mailbox, using accept-and-close behavior. Enable native text input for either the search field or the terminal, using the matching widget key.
