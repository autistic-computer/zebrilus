# Desktop sidebar controller

`desktop_nav_tree` ports the source desktop tree's structural fleet projection, target ownership and sidebar selection state. The actual Rust `MuxTreeModel` and `WorkspaceSidebar` call the extracted source helpers in `zz-client::desktop_nav_tree`; the source reference invokes those same helpers and the existing `zz_client::sidebar::tree_navigation`.

The source-facing projection borrows host/session/window/pane iterators. Its rows carry host, session, window and pane positions into the original fleet. The actual GUI reconstructs labels, pane kinds and programs from those positions, preserving the original payloads and avoiding a fleet clone for each lookup. The Mojo representation retains the structural IDs, active flags, connected flag and renameable names; its row positions are the integration seam for the remaining complete host/presentation envelope. It does not represent terminal planes.

Order follows the source vectors. No early sort or identifier deduplication changes the visible rows. Duplicate nodes overwrite their visible index with the last row, including parent lookups that can refer to a later duplicate. Expandable-node membership includes hidden descendants. The first matching host, session or window controls the source queries where the original code uses `find`; the distinct active-session fold preserves later matching pane updates. Window shortcuts visit only connected hosts and stop after nine windows across the original host/session/window order.

`SidebarTreeState` retains expanded nodes, selection, pointer-selection provenance, active target and the visible projection. It implements local-host introduction, active-follow, expansion pruning, invisible-selection fallback, pointer selection/toggling, direct toggles, all six tree navigation directions and focus restoration. Returned row indices are source `Nearest` scroll intents; this leaf does not implement list layout or pixel scrolling. Reconciliation is called when the complete source model changes, as in the desktop caller. A full-model revision/identity check remains the enclosing fleet coordinator's responsibility.

The controller stages fallible rebuilds in a candidate and publishes only after validation. Admission allows at most 65,536 total structural nodes and 16 MiB of conservative normalized node/name accounting, with at most 65,536 expanded or prior-host entries. Invalid node tags and noncanonical host-node identities are refused. These resource policies are adapter limits, separate from the source's unrestricted collections. The maximum-node probe builds all 65,536 visible rows and checks that a one-node overflow and an oversized name preserve the complete existing selection/projection. No input is truncated.

`python3 mojo/scripts/desktop_nav_tree_vectors.py` compares 96 generated source fleets under 1,152 expansion patterns: 3,960 target/name/expandability queries, 10,674 visible rows and 84,780 navigation results, in 738,593 exact normalized bytes. `python3 mojo/scripts/desktop_sidebar_vectors.py` compares 64 mixed traces with 6,144 state transitions and 161,314 exact bytes. The trace oracle composes actual delegated reconcile/path helpers with actual source navigation decisions; it does not claim universal equivalence to every GUI execution or a formal proof of the sidebar. The Bend input kernel and transaction law counts are unchanged.

Final source client/example Clippy and actual desktop library checks pass; the latter retains its existing unrelated `traffic_light_row` warning. The combined source/typed check peaked at 1,155 MiB. The focused lifecycle plus maximum-node/refusal run peaked at 317 MiB; the standalone probe completed in 0.06 seconds with 59,792 KiB maximum RSS.

The live workspace still uses its existing sidebar. This checkpoint has no `Window`, timeline, keyboard or backend hook. Complete fleet host state/presentation, host-aware action publication, rename and global UI intent consumers are subsequent integration work, alongside the existing complete-map coordinator. A partial configured map is never enabled by this leaf.
