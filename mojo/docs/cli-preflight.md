The cold command path validates the full ordinary CLI chain before starting a daemon. `zzmojo.cli_preflight.preflight` accepts a borrowed span of execution invocations and returns the first resolved command name, the native five-command startup policy, and an optional error with its exact CLI status. It does not change names, arguments, source information, standard input, or other invocation fields.

The catalog is a compact static data string, decoded into bounded runtime records. It carries the actual command names, aliases, native-command membership, positional limits, pinned usage text, and option grammar. Resolution first checks exact names and aliases, then canonical prefixes, with the source ordering and non-native prefix priority. Validation preserves the source handling of short clusters, attached values, optional values, exact long options, end-of-options, `-?`, native extension errors, and `--json` with `-F`. Native commands deliberately retain their source behavior of deferring argument validation to the running server.

The source oracle calls the public Rust `validate_static_command_chain`, `resolve_command`, and catalog metadata. The differential regenerates and checks every catalog record before comparing exact result bytes across names, aliases, prefixes, every option, raw argument bytes, arity boundaries, and errors in later commands. It also serializes invocations before and after each check to detect mutation. Run `python3 scripts/cli_preflight_vectors.py` from `mojo`; the script acquires the shared memory guard. Catalog changes require explicit regeneration with `--generate` and a fresh differential.

The contract is ordinary command-line invocations produced by `split_invocations`: typed configuration blocks and expanded alias groups require a running server. The helper rejects those explicitly instead of treating them as validated configuration text. Warm connections keep server-defined aliases and their existing execution path. Limits remain 4,096 words and 4 MiB across the chain; the catalog is bounded to 128 KiB, 512 commands, and 128 options per command. No generated per-command control flow is compiled.
