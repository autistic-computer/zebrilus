The path service retains typed roots, immutable entry chunks, git marks and captured connection provenance. `path_protocol.mojo` covers all five path-list messages and the native OpenPathPicker event. Text is bounded to 4,096 UTF-8 bytes and each entry/mark batch to 50,000 records, matching the source decoder. The daemon's 64 KiB producer target is not imposed as a decoder limit. A valid larger chunk is checked explicitly.

`differential-path-list` compares 247 accepted frames, 22 rejected frames, 245 independent encoders and eight native Hello capability combinations with the actual Rust serializer/decoder. It preserves optional zero identifiers, Unicode/NUL strings, insertion styles, exact boundaries and the decoder's trailing-byte/nonminimal-integer behavior. The retained-state reference is a verbatim slice of the current native Listing/GitMarks implementation with an isolated shared-text wrapper; the script checks source equality before compiling it. All 160 traces and 800 state transitions agree, including begin errors, updates after completion, empty/final chunks, monotonic flags, root retention, exact-mark replacement and first-directory-prefix precedence. These finite checks do not constitute universal proofs of the path reducer.

`PathService.set_directory` receives the normalized directory from `split_rest`, with its trailing separator. It reuses complete untruncated ancestor listings, cancels incomplete replacements, and accepts replies only for the active request and captured server/client/connection epoch. Error and final-chunk delivery retire the request, so later git/completion messages are ignored as in the source router. Keep one PathService across opens and context changes: its request counter survives close/open and source changes, so canceled in-flight replies cannot collide with a new listing. The captured insertion pane is separate from current focus. `files_place` preserves only explicitly written session/window/pane scope while retaining the resolved host; `start_folder` and `listing_pane` follow native snapshot order and terminal/remote-process policy. Pane map keys and embedded pane IDs remain distinct.

`differential-path-text` compares 11,982 actual source cases and 201,409 exact bytes. This covers directory normalization, split/parent/start paths, plain remote paths, all six insertion styles, raw control rejection, Unicode whitespace/quotes, Windows drive anchors, explicit versus relative insertion, written scope and 1,200 full-snapshot context cases. Those snapshots include missing/dead/nonterminal panes, cross-session scopes, remote foreground processes, map-key/ID differences and numeric map order. The public native `files_place` change exposes its existing implementation for this oracle and changes no behavior.

Retained listing state has a 16 MiB conservative byte budget. Overflow clears rows/root/marks, produces a terminal error and returns a captured-source cancellation command. Rejection occurs before partial mutation. Each worker/UI mailbox is separately bounded to 16 MiB and 4,096 events, and a connection has at most 64 pending path requests. Mailbox overflow reports a connection error and closes the socket, canceling its native work; the UI receives a picker-close notification. A 50,000-entry retained listing, source-stale completions, exact counter wrap, duplicate cancellation, request-count overflow and atomic mailbox append/merge refusals pass focused probes. Entry chunks use shared immutable ownership rather than copying terminal planes or retaining complete snapshot copies.

The worker advertises `client-path-picker-v1` on both ordinary and prepared application connections. Default standalone Hello/connect calls retain their previous bytes unless explicitly enabled. Existing sixteen prepared-startup Hello vectors remain exact. `AsyncBackend.path` queues a `PathCommand` only for its captured connection; the worker checks its epoch and IDs again, registers/cancels it, then writes its native frame without changing terminal selection. The worker routes solicited Begin/Chunk/Git replies and OpenPathPicker events into `backend.paths`. `backend.paths.take().events` transfers ownership to the UI once. Attachment changes and disconnect/reconnect transitions deliver ordered Close notifications. Picker opens retain the source pane/start directory.

`path-list-daemon-smoke` uses a private native daemon and actual worker. It checks exact files/directories/symlinks, native errors, cancellation/replacement, typed delivery once across snapshots, a real choose-path notification, attachment closure and stale queued requests across reconnect. It passed at a 920 MiB build/run peak; source wire/state checks peaked at 510 MiB, context checks at 869 MiB on their first build and 431 MiB subsequently, and focused service/mailbox probes at 227/207 MiB. Every compiler and test uses the shared serial 4 GiB guard.

The live palette's path-level adapter and exact file-row ranking remain integration work. Native `file_rows` uses `zz-client::path_rank`, with the separate typo-aware matcher and its own scoring/highlight rules. The generic palette subsequence matcher is not substituted. The service currently exposes exact retained chunks/marks and native path/context/insertion helpers for that adapter.
