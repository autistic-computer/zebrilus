# Live Panes and Clients choosers

`ChooserSession` and `LiveChooser` connect the retained typed Tree snapshot to the actual Mojo workspace. The implementation currently handles the Panes and Clients modes. `WorkspaceView(..., native_chooser=True)` is an explicit experimental opt-in; the normal window keeps `client-native-chooser-v1` disabled until the distinct Windows palette and Buffer frontend are ready too.

Every action captures the daemon server, client, connection epoch and local chooser scope. The backend checks that source before queuing the native `ChooseTree` request. Chooser requests use the passive action path and do not select an underlying terminal pane. Source changes, final close watermarks and attachment resets retire the previous scope. Item arrays and presentation planes retain their shared immutable allocations.

Physical keys run at their original input-timeline position. Search character keys leave their committed text for `SearchAppend`; other key-down events send the source-normalized Press action, including repeats. Key-up does not navigate. Previously captured terminal releases retain their original passive route. Associated text and command positions from a retired chooser owner are discarded without consuming an unrelated suffix.

The implicit input element has the source's zero-sized IME anchor at the modal origin. It accepts full-range UTF-16 composition and clears composition on each commit. Composed strings, multiple scalars and newlines are forwarded intact through `SearchAppend`; the daemon's prompt engine decides how control characters affect the query. Commits while search is inactive are ignored. Displayed query plus composition is refused atomically above 64 KiB. Callback revisions prevent unchanged preedit from reappearing after a source reset, and captured field/source ownership prevents transferring it to a different surface. These finite checks do not establish complete callback ordering across arbitrary focus changes within one native host pump.

The live adapter measures the committed source renderer before painting. It uses the actual list viewport, snapped row height and logical Body line height, with source non-strict Center and precise/line wheel rules. The list draws no scrollbar chrome. Only the visible row hit records are retained. Left down selects; double down activates; backdrop down closes; the close control requires its matching up. Authoritative hit testing keeps notifications above the chooser opaque to pointer and PRIMARY handling. Clipboard commands and PRIMARY on the modal do not read the host clipboard.

`test-chooser-session` checks source/scope retirement, repeat normalization, UTF-16 composition, unchanged and fresh callback provenance, atomic byte bounds, revision exhaustion and exact scroll values. `test-chooser-live` checks real retained modal focus, row/close/backdrop hits, first-frame centering, wheel travel and IME geometry against the source renderer. `chooser-workspace-smoke` uses a private daemon, compiled Bend envelope gate, two raw PTY recorders and an isolated clipboard. It exercises both native modes, ordered keys and pointer actions, source search resets, composition, activation, focus restoration and oversized preedit/commit refusals that preserve the previous scope, query and composition. Neither underlying PTY receives chooser input. The live workspace check peaked at 2,479 MiB under the shared 4 GiB guard.

The separate `chooser-scene-pixels` task is the source visual proof for the renderer: 126 scenes and 83,349,000 pixels across six themes and three scales. The workspace gesture checks establish live routing and ownership; they do not claim whole-application pixel parity.

Default-constructor regressions also pass: 16 PRIMARY checks, 12 command-output checks, 14 search checks and 11 history checks. The fresh native Swash window build peaked at 2,517 MiB; its six-frame launch and all six CLI-to-GUI startup groups passed from private working directories. The largest regression compiler used 3,584 MiB, within the unchanged 4 GiB guard. These checks used the committed SDK snapshot `6b7acda`.
