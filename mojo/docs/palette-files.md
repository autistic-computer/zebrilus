# File palette adapter

`PaletteFiles` ports the native file level's typed navigation and action policy. It keeps one persistent `PathService` and `PathRanking`, preserves request identifiers across opens, replaces listing generations only when the source coverage rules require it, and schedules only one rank job at a time. `PalettePathWorker` runs jobs on the real native dispatch pool with a persistent source matcher; the UI owns preparation and completion. Shared immutable entry chunks and an independent marks snapshot keep background work separate from live updates.

The controller preserves directory opening versus insertion, parent-name selection, empty filter and caret-action boundaries, copy-and-close versus copy-and-stay, captured insertion panes, current-root folder picking, remote path spelling and native hints. Choosing a directory with Enter inserts or copies it; clicking or Tab opens it. Pending transport retirement preserves cached rows and the local level. The native workspace ignores picker Close notifications instead of dismissing a local palette; a live adapter must not turn that transport signal into modal dismissal.

`differential-palette-files` calls the actual native `FilesLevel` methods and `FilesAction::key` through an isolated test window. All 9,504 cases / 966,048 output bytes agree, including every action key, empty and out-of-range selections, absent roots, Unicode, symlink metadata, copy/insert effects and clipboard results. The fake platform clipboard contains fixture values only. The check peaks at 288 MiB; its source observer build peaks at 699 MiB. `test-palette-files-worker` checks the actual dispatch worker, typed roots and entries, cached-row retention on pending cancellation, and persistent request counters at 293 MiB. Every build and test uses the shared serial 4 GiB guard.

`PaletteFilesRuntime` connects the controller to the actual path mailbox and bounded asynchronous backend. `PaletteRuntime` keeps one persistent worker and service across palette opens; it prepares immutable jobs, polls completion without blocking, preserves same-generation dirty reruns and schedules a wake only while work is active. The file-level component uses the verified input, row, footer and surface widgets, including whole 28-pixel visible rows, native UTF-8 hit ranges, Git marks and the source directory/file icons. Local target context and the captured insertion pane remain separate from the current input focus. Native path insertion sends a pane-addressed Paste without selecting that pane first.

The `insert path` verb opens this level. Native `choose-path` opens it only for a pane in the attached session, retains the supplied absolute/tilde start directory, and performs the same prefix, prompt and chooser cancellation as ordinary palette activation. Alt+Enter copies while retaining the level; Enter inserts or copies and closes; directory clicks and Tab open directories. Shift+Tab returns to the parent. Left/Right/Backspace directory actions require an empty selection and the caret at the end. Clipboard writes use the per-frame host adapter; application notifications use the canonical notification host and survive palette dismissal. Picker Close retires pending transport work while keeping the local palette and cached rows. Connection changes invalidate stale work and rebind future requests.

`differential-palette-ui-keys` compares the footer key parser against the actual native UI keystroke parser: 1,550 cases and 9,581 exact bytes, including modifier-only keys, aliases, minus rules, key characters and Unicode. The pure source controller and the runtime use explicit bounds: 64 KiB of input, 4 KiB per protocol path, 16 MiB retained listings and one background rank job. An overlong directory restores the previous query atomically and reports the refusal before sending a request.

`palette-files-daemon-smoke` checks real listings, immutable chunks, background ranking and exact bracketed paste to a captured pane while another pane stays active. `palette-files-workspace-smoke` exercises the same service through the actual workspace, input timeline and isolated clipboard host at 2,527 MiB. Its exact PTY result is `ESC[200~alpha ESC[201~`; the captured pane receives the insertion while the active pane stays unchanged. The source Scene replay completes for the actual file UI frames. The real application builds at 2,193 MiB, and its six-frame native smoke passes at 219 MiB with complete Scene replay required. The checks do not read or print the user's clipboard. Persistent filesystem recents, remote hosts, folder-pick destinations, the coarse-pointer directory Insert button and broader GUI levels remain separate work. These finite source differentials are not a universal proof of the controller or matcher.
