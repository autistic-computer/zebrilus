The terminal PRIMARY foundation ports the native middle-button policy and press/release state into a bounded Mojo controller. The existing native `TerminalView` calls the same renderer-free Rust policy/state used by the independent reference. Command-output surfaces refuse PRIMARY paste. Ordinary panes yield to application mouse tracking unless Shift overrides it; an accepted middle press consumes its matching release even when the clipboard has no text.

`PrimaryTarget` captures pane, server, client and selection epoch, preserving zero and maximum identifiers. `PrimaryPasteController.press` establishes the release owner and a separate pending paste. Releasing the mouse does not discard that pending payload, so a press and release within one host frame remain deliverable. `accepts` checks the captured context before clipboard access; `prepare` consumes it once, rejects changed context, ignores empty text and refuses text above 4 MiB. Prepared text remains separate from wire bytes so delivery can retain the full application paste allowance.

Run `python3 mojo/scripts/primary_paste_vectors.py`. It compares eight actual native policy combinations and all 6,561 four-step press/release traces: 26,244 transitions and 52,496 exact output bytes. Additional focused checks cover same-frame release, one-shot delivery, source-client changes, embedded NUL/Unicode/newline text, the exact 4 MiB boundary and oversized refusal. The combined native reference/controller build peaks at 1,208 MiB; scoped reference clippy peaks at 294 MiB, under the shared guard.

Live workspace routing remains separate work. It must resolve actual retained terminal hit ownership before any bounded clipboard read, preserve palette/search/toast occlusion, distinguish PRIMARY paste from tracked middle-button input, and deliver the explicit paste at its original input-timeline position. These foundation checks do not establish that live behavior or platform clipboard compatibility.
